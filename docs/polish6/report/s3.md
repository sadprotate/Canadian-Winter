# §3 — Round 5's open items

**Settling is saved.** The relaxation still pending at a save is written into it, in the order it
runs, together with blade_push's random stream. A reload then goes on exactly as the game would
have without it: tested to the last cell. Saves from before this have no queue, so they are
settled once on load. On round 5's mid-winter fixture, a scoop by the street then makes a local
slump instead of a collapse along the street.

The catch is the cost on the worst old saves. Round 5's mid-winter fixture takes ~75 s to settle
(polish5_v3's: ~5 s), and settled, its Maple Street lanes fill in: the 6 m cliffs come down at
load instead of at the first nearby snow work. The menu steps the settle behind "Settling the
snow…", so the window stays responsive. Details in *Settling*.

**The other items:**
- blade_push has its own seeded stream.
- The fast-forward control moves under the clock while the map is open, clear of everything at
  four resolutions.
- A today card's passed start moves to the next hour.
- The large scraper's text reads its 1.0 m from the profile.
- Tools lying in the world rest on the snow or the ground (they floated 0.28–0.52 m), and the 75 %
  pickup still works.
- For §10: the dump truck shares the pickup with plow's code path. Not changed here (STATUS).

## Settling

### What was lost

`Snow` relaxes from a queue of 8 × 8-cell tiles that every snow operation adds to. The queue
wasn't saved. During a sleep the city's pass is a batch that only queues its relaxation, and the
autosave on waking was written before the frames ran it, so a reload lost it. F1's multi-day
jumps make it worse: `Clock.skip` never relaxes, so several passes pile up with nothing settled
between them (open item in STATUS). In round 5's mid-winter fixture the street's edge cells grew
into 6 m cliffs next to 3–5 cm lanes. They stood only because nothing had queued their tiles.

### What changed

- **`Snow.serialize_pending()`** returns two things. `"relax"` is `{"hot": […], "cold": […]}`: the
  hot list from its read index and the cold stack, i.e. the order `_pop_tile` takes them. The
  second is `"push_rng"` (below). `Saves.save_game()` merges both into the save's `snow`, and
  `Snow.deserialize()` puts the tiles back in the same order.
  - Both keys are optional (version 3 stays). `Snow.serialize()` is unchanged, so the suites that
    hash it, polish 3's and 4's game signatures among them, are unaffected.
  - `deserialize` also clears the blade guard. It lasts three relaxation steps and has always
    expired by a save: the sleep fades for 1.7 s first.
- **A save without `"relax"` was written before this**, and is settled once on load. That happens
  in `Saves.load_game`, after the boxes have restored their held cells, which are walls to
  slumping.
  - `Snow.settle_all()` queues every tile and runs the game's own relaxation: the same
    `_relax_tile`, the same queue and order. One difference: a tile queues its neighbours again
    only if it moved more than `SETTLE_MOVED_MIN` (1 mm, summed over its cells) instead of the
    frame relaxation's 0.01 mm. On round 5's fixture that takes 78 s; with the game's own
    threshold it took 134 s, the difference being a tail of sub-millimetre moves. What it leaves
    is ≤ 0.8 mm per cell, which the frame relaxation finishes wherever something queues it.
  - The main menu sets `Saves.settle_later`. Then it steps `Snow.settle_step(250 ms)` a frame at
    a time with "Settling the snow…" on the loading screen, so the window stays responsive.
  - One start at a time (found in review). The loading screen blocks only the mouse, and the
    Continue button kept the keyboard focus, so Enter or Space during the settle started a second
    `_start()` that loaded the save and settled it again. `_start` now returns at once while a
    start is under way (`_starting`, cleared if the load fails) and releases the keyboard focus.
    `test_s3_menu_starts_once_while_settling`: before the fix, Enter, Space, keypad Enter and a
    second press made 5 starts and 5 loading screens; after, 1 and 1.
- Tried and dropped: a second, reversed pass per tile visit (snow running −x / −z across a tile
  in one visit). It took longer (300 s, unfinished) and was removed.

(`before_street_scoop.jpg`). Now it happens at load. The city's next pass clears the lanes again.
The polish5_v3 fixture keeps its lanes.

### A reload continues exactly

`test_s3_settling_saved_midwinter_fixtures`, on each mid-winter fixture after the settle:
1. Make a scoop by the curb (hot queue) and a deposit 2 m in (cold queue), draw once from
   `push_rng`, and save.
2. Run the relaxation to the end in-process.
3. Reload the save and run the same relaxation.

Every cell's depth and loose depth come out identical in both runs. The queue reloads with the same
tiles in the same order (`serialize_pending` equal). Saving again gives the same file, apart from
`saved_at`.

## The weather card

**Diagnosis.** The winter's first snow starts at 10 a.m. on Dec 2 in every seed. Round 5's shot
used `--weather=0`, which forces the sky clear (`Weather.force`, as F1's weather buttons do). What
fell was then nothing, while the card read the schedule: "Light snow … from about 10 a.m.".

In play, the start can't pass without snow. A system that hasn't started shows its start with the
timing error, which is at most ±10 % of the lead, so it's after the issue hour. Once it has
started, the schedule snows through every one of its hours. Checked: 0 of 6,581 today cards
(5 seeds × winters 1–3, every issue hour from 6 h before each system to its end) show a start
before the current hour with none of that day's snow fallen.

**Change.** `forecast_day` handles a system due to be snowing now (`hrs.has(issued)`) while the sky
is held dry (`Weather.held_dry(issued)`: a forced condition, this hour, rate 0). If its shown start
is an hour or more before this one, the card shows the next hour as its start. At 11:14 it says
"from about noon"; at 12:15, still held clear, "from about 1 p.m.". When the force is cleared, the
card reads "from about 10 a.m." again, snow falling. The TV and the computer read the same card
(test and shots). The radio reads `fc_hour`, not cards, and is unchanged. `forecast_audit` and
`weather_truth` are unchanged (below).

**§13's radar** isn't built yet. STATUS binds it: its "now" frame is what is falling now (override
included), with no echo over the town before the card's (moved) start.

## blade_push's own stream

`Snow.push_rng` is a `RandomNumberGenerator`:
- Seeded `PUSH_SEED + year` in `reset_for_winter`, and `PUSH_SEED` at start and for old saves.
- Its state is saved as text.
- `blade_push` takes the same one draw per moved cell from it that it took from `randf()`.

So pushes no longer depend on unrelated draws (audio pitch, effects, the store's slots), and they
no longer advance the global generator.
