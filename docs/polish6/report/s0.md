Readings taken:
- **Point 7's name** is `7_keys_pickup_plow_order`, not `5_…`: the set already has a `5_evening`,
  and the points are numbered in order.
- **"Pending"** in the brief is read as "ordered, not yet fitted". The open order's status is
  `spawned` ("Waiting in the store lot"): bought during store hours, the order is ready at once
  and the store marks the plow `spawned` without putting anything on the pad. (Bought after 9 p.m.
  it would be `pending` until 7:00; §10's migration has to cancel any status but `collected`.)
- **`6_winter2`'s reputation.** Round 5's method (win every residential listing from "New
  listings", clear, re-snow) wins nothing on this build: since round 5 §10 the board only refills
  up to its daily size, so a full board gets no new listings. F1 now has a Reputation row, so "as
  high as F1 allows" is its **Set** at 100, pressed after the old loop (`_p5_raise_reputation`, which
  checks the menu has the row). Unlike round 5's version-2 file, this one has no renewed recurring
  contracts.

**Load check:** `test_polish5.gd`'s fixture test is data-driven over `FIXTURE_DIRS`, and its
comment says the version-3 set is added by listing its folder there, so `polish5_v3/` is now in
that list (one line). `--only=polish5 --test=polish5_fixtures --verbose`: **1 passed, 0 failed,
171 checks** (68.8 s): every polish5 and polish5_v3 file loads, moves, scoops, sleeps to 7:00
with the autosave, and reloads at the same time, money and stage (`fixtures_load.log`). The
polish3 and polish4 fixtures load and play in their suites above.
