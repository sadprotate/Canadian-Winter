# §12 — Every key can be rebound

## The audit

Most of it was already done (STATUS.md, "§12: every key read"):

- All 42 actions the game reads are in `Settings.ACTIONS`, each read somewhere, each shown once in
  Settings → Controls under its group ("On foot", "General", "Vehicles & machines", "Hint panel"),
  this round's included (the hint panel's three, `veh_engine`; round 7's blade keys).
- No gameplay key is read raw. The snowshoes toggle already reads Inventory (held) and Interact; F1
  is already the rebindable `debug` action.
- The settings menu fits every canvas from 1280 × 720 to 3440 × 1440 (`canvas_items` never gives less
  than 1920 × 1080) and the Controls list scrolls.
- Restore defaults gives this round's defaults; the migration keeps custom bindings and gives new
  actions their defaults with no `CONTROLS_VERSION` bump (unchanged code, now tested).

## What changed

- **The conflict check follows every place an action is read** (the owner's answer 9).
  `Settings.shares(a, b)` is now "some place reads both" (`live_actions`), and the places list
  what's really read there: the slot keys in a vehicle (`SLOT_ACTIONS`), fast-forward at a
  walk-behind, F1 at the computer. It refuses what the context rule refused, plus: Move forward on
  the chute's Z (both at a walk-behind), the chute on T (fast-forward at a walk-behind), the horn on a
  slot key (in a vehicle). A foot key and a vehicle key never read together may still share (H: the
  pouch and the horn). No default or saved binding changes; the defaults clash nowhere.
- **The snowshoes toggle:** no change (it reads the actions — the smaller of the two options); the
  doc says so and a test drives it with rebound keys.
- **`docs/features/controls.md`:** an "Exceptions" section (Godot's `ui_*` built-ins, the settings
  menu's Esc, the computer's left-button poll, mouse look, the F1 menu's fields), the place-based
  rule, the snowshoes chord, F1, the readers, the known issues.

## Tested

- New, `--only=polish8 --test=test_s12_` (7, all pass):
  - `every_action_in_the_menu`: every action name read in `scripts/` (calls, `get_axis` /
    `get_vector`, the hint panel's list) is in `Settings.ACTIONS` or a documented exception
    (`ui_cancel`), every action is read, and the menu lists each once under its group.
  - `no_hard_coded_keys`: no `KEY_*` / `MOUSE_BUTTON_*` / `JOY_*` / keycode / key-state read and no
    `ui_*` action read outside `Settings`, except the documented ones; the exceptions are in
    `controls.md`.
  - `every_action_rebound`: all 42 actions, one by one, rebound from the menu (its button, then a key
    pushed into the viewport) to a key bound to nothing: the menu shows it, the input map has it, it
    works with the new key and not the old; then the menu's Restore defaults gives this round's
    defaults.
  - `no_conflict_in_any_place`: the defaults clash in no place; the place-based refusals (walk-behind,
    vehicle, computer, the hint keys); a foot and a vehicle key still share.
  - `migration`: an older file keeps jump on J and gets the engine, hint and blade defaults, version
    2; a custom key where the engine is read (slot 1 on I) keeps it and the engine starts unbound.
  - `snowshoes_follow_the_keys`: Inventory → K, Interact → L: hold K, press L, the snowshoes toggle.
  - `menu_fits_and_scrolls`: the panel within every canvas from 1280 × 720 to 3440 × 1440; the list
    scrolls to its end.
- Also run (all pass): polish5 `test_s2_` (defaults, migration, no conflict, cap, keys shown),
  `test_s7_typing_fires_no_game_action`, `test_s9_auto_return_and_availability`,
  `test_s13b_snowshoes`, `test_s4_gerry_snow_tips`; gameplay `test_settings_rebinding`; polish7
  `test_s11_` (the blade keys); polish8 `test_s17_` (the hint keys); polish6
  `test_s3_menu_starts_once_while_settling`.
