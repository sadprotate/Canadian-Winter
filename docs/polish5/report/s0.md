**Item 12 (`p_elem->_root`), narrowed down.** With a real mouse click on "Sleep until 7:00 a.m."
nothing is printed (10 headless runs, 2 windowed). It prints twice, exactly as in the tests,
when the button's `pressed` is emitted from code resumed on a **physics frame** (`run_log --emit=physics`,
log `run_headless_fun_emit_physics.log`), not when it is emitted from code resumed on a process
frame (`--emit=1`). The same pair appears when the winter summary's "BEGIN WINTER 2" is pressed
that way (make_fixtures, test_winter_summary_and_new_year). Both buttons unpause the tree
(`close_modal`) — the game_root comment on `winter_ended` already notes that pausing/unpausing
mid-iteration makes the engine log SelfList errors. So in the real game this path is clean; the
lines come from tests unpausing during the physics step.

**Item 13 (leaks at exit), narrowed down.** The count varies run to run on the same path: headless

Survival 8 / 4, 0, 8 / 4; windowed 0 in both runs.

the resources `music_calm.wav`, `music_snow.wav`, `ui_click.wav`, `ui_hover.wav`, and the orphan
bus names "UI" / "Music" — the menu music and the EXIT click/hover sounds still playing when
`quit()` runs. Nothing else leaks.

## 0.2 The main-scene run driver

`tests/run_log.tscn` + `tests/run_log.gd`. Commands (also at the top of the script):

    godot --headless --fixed-fps 60 --path . res://tests/run_log.tscn [-- --mode=survival]
    xvfb-run -a -s "-screen 0 1920x1080x24" godot --path . res://tests/run_log.tscn [-- --mode=survival]

It changes to `scenes/main_menu.tscn` and drives the real scenes: PLAY → the mode card's New Game
(→ "Start new game" if a save exists) → the menu's own scene change → ~60 s of play → sleep in the
bed → Esc → EXIT TO MAIN MENU → EXIT (`get_tree().quit()`). Buttons are clicked with mouse events
at their centre (fallback: emit, and it says so — never needed), looking is mouse motion, walking
and scooping are input actions. Each step prints a `[run_log]` line; a stuck step quits with
code 2, a hang with code 3. Options: `--mode`, `--play=<s>`, `--timeout=<s>`, `--emit=1|physics`.
Measured on the baseline: 2 scoops of 30 L, the front door opened with Interact, the bed's prompt
from the bedroom spawn, wake at Dec 2 07:00 with the autosave, back to the menu, exit 0. Headless
runs take ~7 s; windowed ~8 min (software GL).

Readings: "a minute of play" = 60 s of the game's own frame time (24 game minutes on the clock).
The house has no path-finding for a bot, so the driver hops to the hall inside the front door and
later to the bedroom spawn; everything else is walked. Headless can't capture the mouse, so there
(only) it sets `Game.force_input` as the tests do. The saves were deleted before each logged run, so
New Game went straight in; a run with an existing save (the overwrite dialog) is
`run_windowed_overwrite_dialog.log` (same lines).

Every fixture: player's pickup in the driveway (`pickup_plow` in 2), small shovel still buried
(uncovered in 6), Gerry's tutorial complete. Readings and what couldn't be done as written:

- **1_contracts** — Dec 2's board had no recurring listing (day 0's never does: `day > 0`), so the
  recurring one is from Dec 3's. No city contract: those need reputation 58 and a plow/blower
  vehicle.
- **2_upgrades** — "every upgrade bought once". **Baseline bug found:** `pickup_plow` is both an
  upgrade id and a vehicle id, so `Economy.item_kind()` treats the upgrade as a *vehicle*: buying
  "Pickup front plow" in the Upgrades app also puts a second pickup-with-plow in a store bay, and
  `can_buy` never answers "Already owned" (it can be bought again and again). The fixture buys it
  once, so it holds two `pickup_plow` vehicles (the player's, plowed, in the driveway; the extra one
  at the store). Not fixed (§13 owns upgrades).
- **3_vehicle** — the pickup is owned from the start, so the fixture adds a bought vehicle (ATV with
  blade, the smallest) moved into the driveway (the bot can't drive it home), with the keys found and
  the driveway cleared (snow set to bare and the box measured, as the pass-3/4 fixture maker does for
  Gerry's trail).
- **4_midwinter** — 24 and 28 Maple Street exist (lot indices 9 and 10, built lots, neither the
  player's nor Gerry's). With seed 2024 neither is on the board on Jan 19, 20 or 21, nor on F1 "New
  listings" boards for Jan 19/20 (that button returns the same board for every press in a day); Jan
  22's board lists 28 Maple Street. After Jan 20's major event the street in front of the house is
  1.10 m deep (above the hips: the fixture test couldn't walk it) until the grader's next scheduled
  pass (Jan 23 07:35), so the fixture waits for that pass (0.02 m after) and is saved Jan 23 13:00.
- **5_evening** — Dec 3, listings open; no bid placed (not asked).
- **6_winter2** — F1 at this build has no reputation control, so it's raised with F1's own buttons
  on Mar 30–31 of winter 1: "New listings" + winning every residential listing, "Clear all snow" +
  "+1 hour" (one-time +2, first visit +1), then "Add globally" 0.1 m / "+1 hour" / "Clear all snow" /
  "+1 hour" loops (+1 per recurring visit): 73 after the board, **100 (the cap)** at Mar 30 15:00.
  Parking lots were left out (their boxes only complete on an exact count, so in a skip they'd sit
  snowed in and cost −6 each). Then "Clear all snow", F1 "Apr 1", the summary's "BEGIN WINTER 2"
  with every recurring contract ticked (default), and on to Dec 2 12:00.
