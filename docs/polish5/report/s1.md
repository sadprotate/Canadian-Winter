## 1.4 HANDOFF §13 item 12 — `Condition "p_elem->_root" is true` — engine

**Cause (engine, GodotPhysics3D; read from the reproduction below — the engine source isn't
reachable from this VM).** Pausing the tree also deactivates the physics server, and an
inactive server skips its per-frame query flush. Bodies with a state callback (RigidBody3D,
AnimatableBody3D) that the last step before the pause queued for that flush stay queued. If the tree
is then **unpaused from inside the physics frame** — after the (skipped) flush and before the step,
i.e. from `_physics_process` or a `physics_frame` coroutine, or a deferred call flushed there — the
next step queues those bodies again and `SelfList::add` refuses each one: one error line per body.
Nothing else happens (the add is skipped; the next flush empties the list). Unpausing from a
process frame or from input never prints it. Deferring doesn't help (`set_deferred` from the
physics frame prints it too: the message queue is flushed inside the physics frame, before the
step).

**Exact reproduction** (a standalone project, nothing from the game; `/home/claude/p5/s1/item12_repro/`):

```gdscript
extends Node3D  # main scene of an empty GL Compatibility project, Godot 4.7.2
func _ready() -> void:
	var body := RigidBody3D.new()          # AnimatableBody3D too; CharacterBody3D doesn't
	var cs := CollisionShape3D.new()
	cs.shape = BoxShape3D.new()
	body.add_child(cs)
	add_child(body)
	for i in 10:
		await get_tree().physics_frame
	await get_tree().process_frame
	get_tree().paused = true               # from a process frame
	for i in 5:
		await get_tree().process_frame
	await get_tree().physics_frame
	get_tree().paused = false              # from a physics frame -> ERROR: Condition "p_elem->_root" is true.
```

`godot --headless --path .` prints the error once (`./core/templates/self_list.h:46`); with the
unpause after `await get_tree().process_frame` instead, nothing.

**In the game** every unpause (`close_modal` and the rest) runs from a button, a key or a
process-frame callback, so real play never prints it (§0: 12 real-click runs clean). It came from
the **tests**: their button helpers emit `pressed` from a coroutine resumed on `physics_frame`
(`_frames(n)`), and "Sleep until 7:00 a.m." / "BEGIN WINTER 2" unpause the tree. Fix (test code):
those four presses (test_polish3 and test_polish4 `test_playthrough_from_the_menu_both_modes`,
test_gameplay `test_winter_summary_and_new_year`, make_fixtures' winter-2 summary) first
`await process_frame`, which is where a real click arrives. Nothing they assert changed.
`tests/run_log.tscn -- --emit=physics` still reproduces it in the real game (two lines), on purpose.
No game code changed for item 12 (sleep is on the "leave alone" list, and the game never triggers it).

## 1.5 HANDOFF §13 item 13 — leaks at exit — fixed

**Cause (project).** A sound still playing when the engine shuts down stays referenced by the audio
server's playback list: its `AudioStreamPlayback*` and `AudioStreamWAV` are reported as leaked
(`N ObjectDB instances were leaked at exit`) and the WAVs as `resources still in use`, plus orphan
bus-name StringNames. `get_tree().quit()` gave the audio thread no time to drop the players freed
during shutdown, so the count depended on what happened to be playing and on thread timing:
`--verbose` named the menu music (`music_calm`, and `music_snow` left playing at −80 dB after a
game), the EXIT click / hover (`ui_click`, `ui_hover`), and in the test runner the ambience loops
(`wind_light`, `wind_strong`, `blizzard`, `fire_crackle`, `furnace_hum`, `room_tone`) and one-shots
(`gust_whistle`, `power_on`): 10 + 10 instances, 10 resources (`before/tests_polish5_leaks_verbose.txt`).
Nothing else ever leaked.

**Fix.** `AudioMgr.quit(code := 0)`: pause the tree (no node restarts a sound), take the stream away
from every `AudioStreamPlayer`/`2D`/`3D` in the tree (stops it; nothing can replay it), refuse new
`play`/`play_at` and skip the ambience/music update, wait `QUIT_DRAIN_MS` = 150 ms of real time
(the audio thread needs two mix steps, ≤ 25 ms each), then `get_tree().quit(code)`. Used by the
menu's EXIT, the pause menu's "Quit to desktop" (both branches), the window's close button
(`auto_accept_quit = false` + `NOTIFICATION_WM_CLOSE_REQUEST` in AudioMgr) and the tools that load
the game (`test_runner`, `perf`, `grind_bench`, `make_fixtures`). `run_log` now waits up to 5 s of
real time for the quit after EXIT (it used to fail after 30 frames). Exit takes 150 ms longer.
